## 1. 目标和不可变约束

目标是在 **YesMusic 仓库内**运行、构建并打包现有莱茵生命风格原型，同时复用本仓库的 Electron、Node API、网易云交互、音频导出和 Agent 服务。最终用户打开桌面应用时看到新界面，四个入口能使用真实功能；`http://127.0.0.1:5175/` 只作为现有视觉参考，不是交付地址。

不可变约束：

1. 以 `RhineLabWallpaper` 的上述提交为唯一视觉源，迁入完整素材、入口加载动画、3D 场景及交互动效；不从空白页面重画，不用本仓库早期的 `ui-next/` 替代该原型。
2. 保持用户已经确认的布局和动线：左侧工作台与播放器、右侧抽屉、背景失焦、歌单导出后的 3D 档案。功能接入不得顺手改版。
3. 四个入口固定为 **AI DJ 助手、云端歌单、在线搜索歌曲、导出根目录**。不出现“单文件转码”入口；原有 `/api/convert` 暂保留，不在本轮删除后端。
4. 登录入口位于右上角；左侧没有待办清单。真实功能状态不得用三首示例曲目、演示歌单、假倒计时或假成功提示冒充。
5. 除单曲下载缺口和必要的认证/静态资源适配外，优先调用现有 API，不重写网易云请求、音频处理器、Agent 后端。
6. 每个阶段只解决该阶段事项，提交代码前通过本阶段验收；出现缺口要明确报出，不以占位按钮或静默失败宣称完成。

## 3. 状态边界和适配接口

在新 renderer 中建立独立的 `api`、`auth`、`player`、`export`、`agent` 适配层；`workbench` 只消费状态并发送动作，`scene` 只接收需要显示的档案数据。不要在 HTML 拼接、Three.js 绘制函数或每次 `render()` 时发起 `fetch`。

建议统一以下最小数据形状，原始网易云字段仅在 API 适配层出现：

```ts
type Track = {
  id: string; title: string; artists: string[]; album: string;
  coverUrl: string | null; durationMs: number | null;
};
type Playlist = {
  id: string; name: string; coverUrl: string | null;
  trackCount: number; tracks?: Track[];
};
type AsyncState<T> =
  | { status: "idle" | "loading" }
  | { status: "ready"; data: T }
  | { status: "error"; message: string };
type PlayerState = {
  queue: Track[]; index: number; status: "idle" | "loading" | "playing" | "paused" | "error";
  currentTime: number; duration: number; error?: string;
};
type ExportState = {
  playlistId: string; playlistName: string; coverUrl: string | null;
  total: number; completed: number; success: number; failed: number;
  overallPercent: number; phase: "confirm" | "running" | "done" | "error";
  currentTrack?: string; message?: string;
};
```

映射规则：`id` 全程转成字符串，禁止用数组下标作为歌单/曲目身份；`ar[]/artists[]` 映射为艺人名数组，`al.picUrl/album.picUrl` 映射封面，`dt/duration` 毫秒映射时长。真实图片保持原比例，使用完整封面，不再裁出原型占位图的一角。空封面使用明确的默认视觉，不把演示图说成真实封面。服务端可能返回 HTTP 200 但业务 `code` 失败，适配层同时检查 HTTP 和业务响应。每个异步列表要有加载、空结果、错误及重试状态；切换歌单/搜索词时取消旧请求或用请求序号阻止旧结果覆盖新结果。

认证由单一 `auth` 适配器读取现有凭据并提供给 API 层。沿用旧版二维码、Electron 官方登录、手动 `MUSIC_U` 输入三种现有路径；只有获得真实 Cookie 且 `/api/user/playlists` 校验成功才显示“已登录”。旧代码在 QR 结果缺少 Cookie 时有 `MUSIC_U=${unikey}` 兜底，此兜底不能带到新界面。当前后端只有 `/api/user/playlists` 接受 `x-cookie`，其他需鉴权的 GET 路由仍读查询参数；在后端最小补齐统一的请求头读取，再让新 renderer 中需鉴权的 GET 请求用头传凭据。禁止将 Cookie 放进 URL、控制台或服务端日志；现有 `server.js` 的歌单请求日志会输出完整 Cookie，`lib/audio-exporter.js` 也会输出含 Cookie 的请求头及带临时鉴权参数的音源 URL，应在接入对应阶段去掉这些敏感日志。POST 继续按现有请求体合同传递，后续可再单独改认证机制。

## 4. API 与页面动作对照

下表以当前 `server.js` 和旧版调用为准；网易云上游响应并未全面标准化，适配器要容忍缺字段，但不能默认为“成功”。

| 新界面动作 | 现有路由/桥 | 关键输入和输出 | 接入要求 |
| --- | --- | --- | --- |
| 扫码登录 | `GET /api/login/qr/key`、`GET /api/login/qr/check?key=...`；Electron `openNeteaseLogin()`/`onCookieCaptured()` | QR 返回 `unikey/qrImg`；轮询码 800/801/802/803；成功时须有真实 Cookie | 停止轮询并清理监听；失败/过期可重试；右上角同步账号状态 |
| 歌单列表 | `GET /api/user/playlists` | `{code:200,userId,playlists:[{id,name,trackCount,coverUrl}]}` | 登录后/刷新时请求，空列表与失败分开显示 |
| 歌单详情 | `GET /api/playlist/detail?id=...` | `playlist.tracks[]` 为原始网易云曲目 | 以真实封面/曲目数/歌曲展示；未返回的更多歌曲不能伪造 |
| 新建、删除歌单 | `POST /api/playlist/create`、`POST /api/playlist/delete` | 创建 `{name,privacy,cookie}`；删除 `{id,cookie}` | 服务端确认成功后刷新列表；删除需二次确认；失败不改本地列表 |
| 歌单加/移曲目 | `POST /api/playlist/tracks/update` | `{op:"add"|"del",pid,trackIds,cookie}` | 成功后重拉对应详情；失败保留原曲目 |
| 在线搜索 | `GET /api/song/search?keywords=...&limit=30&offset=...` | 原始 `result.songs[]` | 空词不请求；搜索词变化时防旧结果覆盖；显示真实歌曲 |
| 获取播放音源 | `GET /api/song/url?id=...` | `data[0].url`，可能为空或过期 | 每次开始播放/切歌时获取新 URL；无音源展示可理解错误，不假装在播 |
| 导出目录 | Electron `selectDirectory()`；浏览器可手填 | 选择/填写本机路径，传给 `outputRoot` | 保存设置、回显、验证非空；浏览器不能选目录时提示手填；未确定路径不启动导出 |
| 歌单导出 | `POST /api/playlist/export`，`Accept: text/event-stream` | `{id,name,outputRoot,cookie}`；`start/urls/track/progress/track-done/track-fail/done/error` | 见第 6 节；真实进度驱动 3D 屏幕 |
| Agent 会话 | `GET/POST /api/sessions`，`GET/PATCH/DELETE /api/sessions/:id` | `{sessions}`、`{session}`、`{session,messages}` | 服务端 SQLite 为真相源，不再用原型 localStorage 会话充数 |
| Agent 对话 | `POST /api/agent/chat`，SSE | `{message,sessionId,cookie,config}`；`text/reasoning/tool_start/tool_progress/tool_result/status/card` | 逐帧渲染，可停止；卡片操作连到真实播放器/搜索/歌单 |
| 播放卡片单曲下载 | **当前没有对应路由** | `lib/audio-exporter.js` 已有 `downloadAndExportTrack()` | P3 新增 `POST /api/song/export`：接收 `{id,outputRoot,cookie}`，服务端按 ID 获取真实元数据和音源，复用现有下载/转码与文件名清洗；返回实际结果或错误，不让页面自行写文件 |

默认运行端口由 `server.js`/`main.js` 设置为 4178，Electron 加载同一 HTTP 服务。上表的参数、服务端行为以代码为准，`docs/API_DOCUMENTATION.md` 的导出进度比例描述与当前实现细节存在差异；前端直接采用事件中的 `overall` 字段，不自己重新计算百分比。

## 5. 分阶段实施任务与单阶段验收

每阶段独立提交，提交信息写清阶段号。先跑完本阶段的构建和对应验收，再进下一阶段；阶段中不做无关视觉重构。建议将契约转换和状态机写成可离线运行的小测试，端到端检查只覆盖关键用户路径。

### P0：迁入视觉源并接入桌面壳

实施：在本仓库建立 `renderer/`，完整迁入固定提交中的运行时源码、资源、字体/模型、启动动画和许可证信息。新增 `build:ui`，将资源构建到 `public/dj/`，Vite 开发模式代理 `/api`。验证现有静态服务能提供 `/dj/` 的 HTML 和资源，必要时补齐目录首页映射/MIME；打包脚本先构建新 UI。保留旧页面为根路径，暂不切默认。将 `prototype/host.js` 的视觉初始配置转换为新界面的正式启动配置，同时去掉其中注入的样本播放数据；不能简单删除它导致工作台不出现。

验收：全新克隆本仓库后仅安装本仓库依赖，即能构建并在 `http://127.0.0.1:4178/dj/` 打开；入口动画、3D 模型、字体、音效、所有贴图正常，无 404 和控制台致命异常；关闭 sibling 仓库与 5175 服务后仍正常；设置 `YESMUSIC_UI=dj` 时，`npm run build:dir` 生成的 Electron 包能打开同样页面。此阶段 API 可显示“未连接”，但不能显示假在线成功。

### P1：认证、账户与云端歌单

实施：抽出 API/认证适配层；接通右上角登录、退出、重新登录，读取真实歌单列表/详情，新建/删除、增删曲目。删除硬编码 `djPlaylists` 对正式页面的控制；演示数据只允许在显式 mock 模式。补齐 GET 认证头、删去 Cookie 明文日志。

验收：有效账号扫码或 Electron 官方登录后，右上角变为已登录，云端列表与旧版同账号数量和名称一致；刷新页面后仍能重新验证；选择任意歌单，封面、歌曲数及曲目与 API 一致。创建、添加、移除、删除各做一次，服务端确认后重新获取的数据一致。取消删除无请求；失效 Cookie 显示重新登录，空歌单和网络错误各有单独状态。退出后不再展示上个账号的云端数据。

### P2：搜索和真实播放器

实施：接通搜索、播放音源及统一播放队列。云端歌单封面“全部播放”和单曲播放设置队列；搜索结果播放设置搜索队列；左下卡片、3D 歌曲档案、抽屉内播放按钮全部订阅同一个 `PlayerState`。使用一个 `HTMLAudioElement`，以其 `loadedmetadata/timeupdate/play/pause/ended/error` 为时长、进度、播放状态来源。上一首/下一首按队列切换，并同步背景档案；拖动进度条设置 `audio.currentTime`。未登录、无版权、URL 失效及浏览器阻止自动播放必须可见。

验收：使用真实歌单 3 首以上，全部播放后左下角显示真实当前封面、歌手、时长；下一首、上一首后音乐、卡片和背景档案一致；点击卡片进入 3D 歌曲档案；拖动到歌曲中段后声音与时间同步，曲终按队列前进；播放失败不会留下“正在播放”的假状态。切换到搜索结果后队列确实更换，不沿用旧歌单。

### P3：目录、单曲下载和歌单导出

实施：接通输出根目录设置，持久化非敏感路径（建议键 `yesmusic-output-root-v1`），默认沿用旧版 `D:\DJ_Music_Library`，导出前校验非空；Electron 通过 `selectDirectory()` 选目录，浏览器允许手填。补齐单曲下载真实 API 并调用现有 `lib/audio-exporter.js`，测试路径和失败；歌单导出使用现有 SSE。歌单卡片的导出按钮在**列表页**询问，详情页的导出按钮在**详情页**询问；取消不发请求，确认后右侧保持触发时的页面，背景切换为导出模型并取消背景失焦。3D 屏幕呈现真实封面约占屏幕内一半、右侧歌曲数与状态、底部真实进度；屏幕由磨砂转清晰，画面居于左侧露出的视觉区域。原型 420 ms 假定时器必须删除。资源遮挡和前景深度关系沿用当前视觉修复，不能出现穿模。

验收：设置实际可写的临时目录，确认弹窗出现时无任何文件写入；取消后页面和文件系统不变；确认后只切换背景，右侧仍可见触发导出的歌单列表或详情。3D 上歌单名称、真实完整封面、真实曲目总数、已完成/失败数及 `overall` 实时更新。成功时目录中出现与成功数一致的音频文件；部分失败时显示成功/失败数而不标成全成功；`error`、连接断开或无 `done` 时展示失败/未知状态，绝不显示 100% 成功。完成后视角正常，模型画面、封面、文字和进度仍保留，返回工作台后可继续操作。单曲下载有独立真实成功/失败检查。

### P4：Agent 会话与功能卡片

实施：用 `/api/sessions` 替换 `dj-agent.ts` 的 localStorage 演示会话；用 `/api/agent/chat` SSE 替换 `demoReply` 和延时回复。保留现有 Agent 抽屉布局、提示词入口、设置与工具状态视觉。Agent 返回卡片时走同一播放器、搜索和歌单动作，而非独立的演示曲目。停止按钮中断请求；会话切换时不把旧响应写到新会话。

验收：新建、重命名、切换、删除会话和刷新后恢复都以服务端数据为准。发送消息能逐步显示文本/状态/工具过程；停止后流停止，页面可再次发送；`card` 中的歌曲可进入真实播放器，跳转搜索或歌单仍保持一致状态。服务不可用时显示错误，不能退回固定演示回复。真实 Agent 外部服务需要授权/配置时，使用离线 SSE 契约测试和一次获授权的实测，分别记录结果。

### P5：默认入口切换与交付

实施：四个入口全部通过后，把 `/` 默认映射到新页面，并保留 `YESMUSIC_UI=legacy` 启动回退；清理生产构建中 `djDemoTracks`、示例歌单、演示导出和演示回复的业务路径。保留视觉素材中纯装饰文字可以，但业务数据必须来自真实状态。更新 README 中启动、构建、打包和回退命令。

验收：`npm start` 与 `npm run electron` 默认打开新 UI；设置回退变量可以打开旧 UI；关闭 5175 服务后完全可用。无登录时清楚显示待登录/功能受限；正式构建里搜索不到可触发的示例业务数据或假进度。旧版 `npm test` 全过，UI 构建和 Electron 打包通过。

## 6. 导出状态机与 3D 映射（重点）

唯一流程：`idle → confirm → running → done | error`。`confirm` 阶段不切页、不切场景、不写文件；`running` 阶段右侧触发页保持，背景失焦取消并切到导出档案；`done` 或 `error` 阶段保留右侧触发页和模型的最后一帧内容。用户主动关闭抽屉不等于取消服务端导出，界面重新打开仍能看到本次任务状态；若当前后端不支持安全取消，不能画一个实际上不会终止下载的“取消导出”按钮。

| SSE 事件 | 状态更新 | 3D 屏幕 |
| --- | --- | --- |
| `start` | 使用事件 `total` 初始化真实总数；进度 0 | 设置歌单 ID、名称、当前封面、总歌曲数 |
| `urls` | 阶段为获取音源，使用 `overall` | 底部进度更新，右侧阶段说明变化 |
| `track` | 当前处理歌曲、`completed`；并发时不要用单曲 `index` 当已完成数 | 右侧当前曲目/阶段变化 |
| `progress` | `overall` 为总体百分比；`percent` 仅为单曲百分比 | 底部总进度采用 `overall`；可额外展示速度 |
| `track-done` / `track-fail` | 增加成功/失败数；优先采用事件累计 `completed` 防重复帧 | 已处理数、失败数同步 |
| `done` | 以服务端 `successCount`/`failedCount` 覆盖最终数；0 首的歌单也可能直接 `done` 而没有 `start` | 100% 仅表示任务结束；有失败时写“部分完成”，不能写“全部成功” |
| `error` / 网络断开 | 保存错误，终止“进行中”状态 | 保留歌单封面和已收到的进度，给出失败/未知结果 |

SSE 解析器要支持一个 JSON 帧跨网络分块、一个分块多个帧、`\r\n` 与 `\n` 换行、`data:` 前缀及读取结束时的缓冲区；只在收到 `done` 后宣称完成。进度夹在 0–100 之间，后到的旧帧不倒退已显示的总体进度。当前代码的 API 文档称 URL 阶段占 0–10%，而 `server.js` 实际发出 0–5% 的 `urls` 帧，故不能按文档自己计算。`src/scene.ts` 目前 `setExportProgress({name,completed,total,cover})` 需要扩展以接收总体百分比、成功/失败和阶段文字；不要为了接入接口重做模型几何。
